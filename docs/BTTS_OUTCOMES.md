# Championship BTTS outcomes (OFFLINE, research only)

`GET /api/v1/research/btts/performance?competition=E1` and
`/research/btts/performance` expose frozen forecasts, final scores, Yes/No outcomes,
missing results and fixture-weighted probability metrics. Both are read-only;
the API uses `Cache-Control: no-store`. Corner endpoints and settlements are unchanged.
The original predictions list remains unchanged; BTTS outcomes live in this separate view.

## Identity, cohorts and sample policy

The inventory validates `btts-research` frozen forecasts/comparison bundles and
odds-free `research-predictions`. Identical BTTS forecast hashes are one cohort,
with both origin labels if present in both stores. Forecast IDs are canonical hashes
of the original BTTS forecast, not comparison IDs or the outer prepared-record ID.
Original provider IDs, probabilities, model versions, input hashes and timestamps
are retained. No models are trained or forecasts generated by settlement.

An exact fixture is `(E1, exact canonical home name, exact canonical away name,
UTC kickoff instant)`. Cross-provider records may share this identity; no fuzzy
names, adjacent dates or reversed venues are joined. Conflicting identities for a
provider fixture ID, or two IDs within one provider for the same exact fixture,
fail closed. Unknown/missing joins remain unresolved; there is no implied No.

Policy `e1-earliest-frozen-per-exact-fixture-v1` selects the earliest frozen forecast
per exact fixture, then the lexicographically smallest forecast hash on a tie.
This selection happens regardless of results or odds. All cohorts are visible,
with an explicit inclusion flag. Yes and No are one binary forecast; books and
repeated snapshots contribute zero additional fixtures. Thus 38 comparisons across
11 fixtures are at most 11 scored matches, depending on verified result coverage.
This V1 model contract permits only the existing DeepFC BTTS version.

Brier is mean `(p_yes - actual_yes)^2`; log loss is mean binary natural-log loss,
clipped to `[1e-15, 1-1e-15]`. Only settled primary fixtures enter either metric.
Zero samples produce null scores. Calibration uses five fixed bins of width 0.2,
left-inclusive/right-exclusive except the final bin includes 1; empty bins are
omitted. Counts and a small-sample warning accompany descriptive frequencies.
No baseline, profit, stake, recommendation or significance claim is included.

## Explicit offline commands

Use the forecast ID from the read-only view. Operate on a disposable state copy
first. Each command emits only a fixed receipt and `provider_requests: 0`.

```sh
PYTHONPATH=src python -m modelfc.btts_outcomes \
  --state-dir DISPOSABLE_STATE --forecast-id ORIGINAL_BTTS_FORECAST_HASH csv \
  --csv-file REVIEWED/E1_2627.csv --csv-sha256 REVIEWED_FILE_SHA256 \
  --retrieved-at ACTUAL_SOURCE_RETRIEVAL_TIMESTAMP

PYTHONPATH=src python -m modelfc.btts_outcomes \
  --state-dir DISPOSABLE_STATE --forecast-id ORIGINAL_BTTS_FORECAST_HASH sportmonks \
  --manifest REVIEWED_MANIFEST --manifest-sha256 REVIEWED_MANIFEST_SHA256 \
  --response-file SAVED_RESPONSE --calendar-file SAVED_CALENDAR
```

CSV requires genuine Football Data **football-data.co.uk** source bytes, reviewed
by the operator; hashes attest byte identity, not publisher authenticity. Never
construct a production CSV from another provider's results. The CSV filename must
be the matching canonical E1 season file. Explicit hash pins use the shared bounded
regular-file reader, rejecting links and concurrent mutation. The source retrieval
time must be actual, timezone-aware, after kickoff and no later than acceptance.
The original file hash, retained row hash/index, retrieval time and actual recording
time are kept. The full file remains private operator evidence.

The CSV join requires one exact home/away/date row and matching London-local kickoff
minute (including DST); missing Time and the ambiguous repeated autumn hour are not guessed. All rows must belong to E1.
Full-time goals must be nonnegative integer strings and FTR must agree with them.
CSV BTTS eligibility requires valid final goals and FTR, independently of corner
counts. Missing HC/AC values or columns do not block BTTS; research corner outcomes
still require both complete nonnegative corner counts. Existing saved outcomes
remain immutable. Blank/incomplete scores, duplicate rows, explicit
nonfinal status, postponed/abandoned records or mismatched identities are rejected.
A complete authoritative FTR/score row is the CSV final-state attestation; V1 does
not acquire an independent calendar for CSV. Missing or suspect evidence must wait
for an eligible source. CSV operation does not import Sportmonks evidence/adapters.

Sportmonks uses the existing pinned manifest, strict FT result normalizer, explicit
team bindings and independent completed football-data.org calendar score/identity
validation. Existing saved bytes suffice; no network calls occur. Original and
normalized hashes, provider fixture IDs, capture reference and calendar provenance
remain in the immutable outcome. A football-data.org forecast also requires the
same calendar fixture ID. The existing complete-corner eligibility restriction in
the saved-result normalizer remains; goals-only/incomplete bundles are unresolved.

## Immutability and access

One deterministic `btts-outcomes/<exact-fixture-hash>.json` is atomically published
under the existing state lock and the BTTS inventory read lock, containing the selected original forecast and
validated result source. Its first recording timestamp never changes. Replay with
identical source/result reuses the record, including when another cohort of the
same fixture requests it. Different scores **or different evidence** conflict;
there is no correction/overwrite switch. Reuse requires the exact original pinned
CSV file and retrieval time or saved bundle. Appending unrelated CSV rows therefore
requires replaying the retained original file, not a newly downloaded copy.

Writers acquire locks in state → BTTS order. BTTS namespace creation also takes
the state lock, so a research writer cannot add a cohort between settlement's
final inventory validation and publication, including odds-free-only states with
no research namespace. The command never creates an empty research namespace.

Read-time validation checks the outcome hash, original forecast, exact fixture,
source and grade. It needs no raw CSV, provider response, calendar or credentials.
Only published outcome evidence and existing forecast ledgers are readable.
The narrow existing publication ACL opt-in supports this new outcome namespace;
no root grants, service units, installed configuration or permissions are changed
by this PR. No source inventory, odds capture, corner ledger or history gate is
written by settlement. Existing seven corner outcomes must remain byte-identical.
